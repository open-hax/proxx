# Agent Task: Implement the proxx EDN Policy Engine on top of `staging`

**Repo:** [open-hax/proxx](https://github.com/open-hax/proxx)   
**Base branch:** `staging`   
**New branch:** `feat/policy-engine` branched from `staging`  
**Primary context:** review and extend [PR #201](https://github.com/open-hax/proxx/pull/201) rather than duplicating its CLJS foundation work. 

## Objective

Implement a **data-oriented model router / policy engine** in ClojureScript for proxx as a depth-first continuation-passing search over an AND-OR decision tree, expressed as EDN policy data. This engine must sit on top of the CLJS runtime foundation already introduced in `staging`, not beside it. 

The engine must route a request context across provider/model/credential branches until it reaches a terminal strategy node that either:
- succeeds and returns a response, or
- fails and yields `nil`, allowing the nearest enclosing choice point to continue to the next candidate branch.

The search state is the tree position itself. Backtracking is encoded by `:eval/op :some`. Failure logging is a write-only trace side channel and must not influence branching.

Do **not** reimplement schema bootstrapping, runtime loading, or CLJS test infrastructure. Extend what is there.

## Architectural model

Treat the router as a proof search over an AND-OR tree:

- `:eval/op :some` = OR node / choice point / backtracking node
- `:eval/op :all` = AND node / conjunction
- leaf predicate = pure condition over `ctx`
- leaf strategy = effectful terminal action in Clojure world

Interpretation rules:

1. `nil` means failure.
2. Any non-`nil` value means success.
3. `:some` returns the first non-`nil` child result.
4. `:all` returns `nil` on the first `nil` child.
5. Filters narrow the context passed to descendants.
6. Strategy failures must not throw out of the interpreter; they become `nil`.
7. The trace is append-only observability, not state.

## Vocabulary contract

Use these names consistently:

- **eval node** = recursive interpreter node
- **predicate form** = pure quoted form evaluated against `ctx`
- **quantifier** / **op** = `:all`, `:some`, `:none`, `:not`, `:assert`
- **policy node** = condition + filters + outcome + children/strategy
- **strategy node** = terminal policy with `:contract/kind :strategy`
- **trace entry** = write-only audit event
- **router** = top-level evaluator over root policy list/tree

Avoid inventing extra abstractions unless forced by tests.

## Interpreter implementation

### `src/proxx/policy.cljs`

Implement the pure recursive interpreter.

Public API:

```clojure
(eval-node policy ctx trace)
```

Where:
- `policy` is one policy node
- `ctx` is the current immutable evaluation context
- `trace` is `(atom [])`, append-only
- return value is either a concrete success value or `nil`

Required helpers:

```clojure
(eval-forms op forms ctx trace)
(eval-form form ctx trace)
(apply-filters filters ctx trace)
(run-strategy policy ctx trace)
(apply-target ctx target item)
```

Semantics:

- `:policy/condition` absent means pass
- `:policy/filters` absent means ctx unchanged
- `:policy/outcome :reduce` means evaluate `:policy/children` as a `:some` choice over child policies
- `:policy/outcome :apply` on a strategy node means run the strategy and return its result
- `:policy/outcome :try` on a strategy node means same execution semantics as `:apply`, but parent `:some` remains the continuation point on `nil`
- `:policy/outcome :next` returns `nil` without running any strategy
- `:eval/target` binds a collection slice of ctx and evaluates children against each item as appropriate

Important design rule: iteration belongs to predefined ops, not arbitrary user forms.

That means:
- quoted forms are atomic predicates or accessors
- collection traversal happens only in interpreter code
- no user-authored arbitrary loops in EDN

### `:eval/target` semantics

For filters over `:credentials`, implement narrowing by evaluating the filter against each candidate item and keeping only those that pass.

Recommended pattern:

- bind each candidate item into ctx as `:it`
- preserve original ctx keys
- replace `:credentials` in child ctx with the filtered vector

So a filter can inspect both `ctx` and the current candidate via `:it`.

## SCI evaluator

### `src/proxx/policy/eval.cljs`

Implement a safe SCI evaluator for quoted predicate forms.

Requirements:

- bind `ctx`
- bind `it` to `(get ctx :it)` when present
- allow a tight whitelist only
- catch evaluation exceptions and return `nil`

Whitelist should include at minimum:

- `=`
- `not`
- `and`
- `or`
- `get`
- `get-in`
- `first`
- `second`
- `keyword`
- `str`
- `clojure.string/includes?`
- `clojure.string/split`
- `clojure.string/starts-with?`
- thread macros if SCI setup supports them ergonomically

Also expose a small hook for invoking contract predicates such as `contract/apply` if needed, but only through an explicit injected function map — not arbitrary symbol resolution.

## Strategy layer

### `src/proxx/strategies/openai.cljs`
### `src/proxx/strategies/anthropic.cljs`

Implement terminal strategy functions as effectful CLJS functions.

Signature:

```clojure
(chat-completions-passthrough ctx) ;; => js/Promise response | nil
(messages-passthrough ctx)         ;; => js/Promise response | nil
```

Rules:

- Use `js-await` from `shadow.cljs.modern`
- Never use `.then`
- Return `nil` on failure conditions
- Catch HTTP/network exceptions and convert to `nil`
- Expect the selected credential in `:it` or in narrowed ctx, depending on the branch shape
- Do not embed policy logic into strategies; they execute, they do not decide

## Loader

### `src/proxx/policy/loader.cljs`

Implement policy loading from EDN resources.

API:

```clojure
(load-policies! path-or-resource-root)
```

Behavior:

- read EDN
- validate each policy against Malli
- throw `ex-info` on invalid policy with offending node in ex-data
- return validated policy vector/tree

This loader is the boundary between data and interpreter.

## Router

### `src/proxx/policy/router.cljs`

Implement top-level request routing.

API:

```clojure
(route-request! policies ctx trace)
```

Behavior:

- run policies depth-first via `some`
- return first success
- if all exhausted, throw `ex-info` with:
  ```clojure
  {:proxx/exhausted true
   :proxx/trace @trace}
  ```

This is the external entrypoint that TS should call through the runtime bridge if needed.

## Integration review for PR #201

Before implementation, review PR #201 with this lens:

### Facts
- It already establishes CLJS as an active runtime dependency in `main.ts` and `cljs-runtime.ts`. 
- It already adds `schema.cljs`, `processor.cljs`, and `runtime.cljs`, which are the natural substrate for your policy engine. 
- It already updates build/test workflows to compile and run CLJS tests. 

### Interpretation
- `staging` is now the right architectural branch for policy routing work because the TS→CLJS bridge is no longer speculative; it is active infrastructure. 
- The policy engine should be the next CLJS-owned domain, not another TS routing layer. 

### Narrative risk
- Do not sprawl the engine across both TS and CLJS. Keep decision semantics in CLJS, and use TS only as the transport boundary. This avoids recreating the exact split-brain architecture the refactor is supposed to dissolve.
